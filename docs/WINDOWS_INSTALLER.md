# Windows installer release evidence

See the [release guide](RELEASING.md) for the complete 0.1.4 release flow and
the [in-app update contract](ROLLING_UPDATES.md).

Target installer: `Skai-Desktop-0.1.4-Setup-x64.exe` (per-user NSIS). The installer creates Start menu and desktop shortcuts, permits install-location selection, and retains user data on uninstall.

## Local lifecycle smoke

The unsigned Windows smoke installs the previous release, launches its packaged smoke, upgrades to 0.1.4, verifies a user-data marker survives, launches the new packaged smoke, silently uninstalls, then verifies application files are removed while user data remains. The run passed on Windows 11 x64 (build 26200). Both installers and uninstallers reported `NotSigned`, so this is development-only lifecycle evidence, not signed release evidence.

The JSON generated by `scripts/smoke-windows-installer.cjs` includes artifact hashes, signature statuses, OS version, and lifecycle assertions. Signed CI is configured to publish this file as `windows-install-lifecycle-evidence.json` alongside the installer.

## Signing requirements and setup location

To sign, first obtain a publisher Authenticode code-signing certificate from a trusted certificate authority. A self-signed certificate will not produce a trusted installer. Export the certificate and private key as a password-protected PFX if the provider permits export; hardware-backed certificates need a signing service and are not compatible with this PFX workflow as written. Configure repository Actions secrets and variables in GitHub; never place private signing material in the repository, chat, or workflow logs.

In that GitHub Actions page, add these repository secrets:

- `WINDOWS_CODESIGN_CERT_BASE64`: base64 text for the PFX file. Create it locally with PowerShell: `[Convert]::ToBase64String([IO.File]::ReadAllBytes('C:\path\publisher.pfx')) | Set-Clipboard`, then paste directly into the GitHub secret field. Do not put it in chat, a commit, or a workflow log.
- `WINDOWS_CODESIGN_CERT_PASSWORD`: the PFX password.
- `RELEASE_GPG_PRIVATE_KEY`: armored private signing key for the Linux archive, because enabling the release signing gate also requires Linux detached-signature evidence.

Under the same page's **Variables** tab, add:

- `WINDOWS_CODESIGN_TIMESTAMP_URL`: the timestamp service URL specified by the certificate provider.
- `RELEASE_SIGNING_READY`: `true` only after the secrets and timestamp URL are saved.
- `PACKAGED_SMOKE_READY`: `true` after exact artifact smoke is accepted.
- `ELECTRON_PACKAGED_READY`: `true` after the supported platform/package checks are accepted.

After the fixes and acceptance gates are complete, the `v0.1.4` tag triggers the release workflow. It signs the Windows app, Agent Host, installer, and uninstaller, then verifies signatures and lifecycle behavior. Review the published `windows-install-lifecycle-evidence.json`, signature manifest, and checksums. Do not create the tag while the release gates are failing.
